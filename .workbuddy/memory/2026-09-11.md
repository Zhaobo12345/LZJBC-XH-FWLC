## 新建工人合同落点修正：worker_draft 在详情页=「撤回后」视图，应落「拟定中（发起方）-新」页
- 用户验收指出：上一轮把新建合同置 `worker_draft` 并跳详情页，详情页 `worker_draft` 状态的 Banner/版本/变更记录写死「合同已撤回至拟定中…」「初始版本（拟定中·撤回后）」「撤回确认」等**撤回后**口吻，与「新创建」逻辑不符。结论：`worker-contract-detail.js` 的 `worker_draft` 仅表示「撤回后」；规范里真正的「新创建」视图是 `worker-contract-draft-initial-new.html`（字面「拟定中（发起方）-新」，其版本/变更记录写「首次创建合同，当前版本」「当前为拟定中状态，暂无变更记录」）。
- 修复（2 文件，不影响其他功能）：
  1. `create-contract.html` `handleWorkerSubmit` 新建分支：跳转目标 `worker-contract-detail.html?id=…&viewer=sender` → `worker-contract-draft-initial-new.html?id=<新id>`。
  2. `worker-contract-draft-initial-new.html` 改造成「按 ?id 加载真实合同」：head 引入 `contract-store.js`；新增 `currentContractId` / `getQueryParam` / `loadFromQuery()`（有 ?id 时用 `ContractStore.getContract` 回载 name/type/amount/group/partyA/invitations，并按 `STAGE_TEMPLATES[type]` 补 contentIntro/stages、缺附件补默认；无 ?id 保留固定示例数据，原型导航不变）；`doSubmit`/`doSave` 增加真实 id 分支：`patchContract` 回写编辑值 → `submitInvite` 推进到 `worker_inviting` 并生成邀约消息 → 跳详情页「确认中（发起方）」。
- 校验：3 个 JS 文件 `node --check` 通过；create-contract / -new 页 HTML 标签平衡 BALANCED。
