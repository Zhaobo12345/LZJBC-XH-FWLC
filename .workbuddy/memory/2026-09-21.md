## git 提交失败排障（嵌套仓库导致 fatal）
- 现象：`git add -A` 报 `error: '.workbuddy/_tmp/protodesign-audit/' does not have a commit checked out` → `fatal: adding files failed`；之后 `git commit` 因无暂存内容也失败。
- 根因：`.workbuddy/_tmp/protodesign-audit/` 内部含一个自己的 `.git`（仅 HEAD/config、无 commit），Git 把它当嵌套仓库/子模块处理，检不出 commit 即 fatal。**那些 `LF will be replaced by CRLF` 只是 `core.autocrlf=true` 的行尾归一化提示，无害、不阻断提交**（全项目 80 行状态里仅此一处 fatal）。
- 修复：项目根新建 `.gitignore`，加入 `.workbuddy/_tmp/`（我的脚本/下载缓存/临时审计产物，本就不该入库，且一并排除该嵌套 .git）。`git add -A` 复跑 → 无 fatal，暂存 77 文件（72 HTML + memory md + .gitignore + shared/doc-viewer/* + skills/auto-distill-skill/SKILL.md），protodesign-audit 确认未入。
- 教训：① 任何 `curl`/克隆下载到项目内（尤其 `_tmp`）前，先确认不会带入 `.git`；若带入，优先用 `.gitignore` 屏蔽整个 `_tmp` 而非删 `.git`。② 用户提交前若再遇同类 fatal，先 `find . -name .git -type d | grep -v '^\./\.git$'` 定位嵌套仓库。
