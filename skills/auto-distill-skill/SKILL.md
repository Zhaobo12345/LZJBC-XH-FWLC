# auto-distill-skill（自动沉淀元技能）

## 目的

把本空间（项目工作区）内反复出现的需求，自动整合为可复用、可触发的 skill。
解决"每次同类任务都从零摸索"的问题——当某一类需求在跨会话的全部问答中出现 ≥2 次，
就把它沉淀成一个结构化的 skill 包，供后续会话或子 agent 直接调用。

本 skill 自身是"元技能"：它产出的新 skill 也会带 `agent_created: true`，
从而可被 `skill_manage` 后续修改或删除。

## 何时使用（触发条件）

满足以下任一即触发本 skill：

1. **重复需求检测**：在回应或复盘用户请求时，判断当前需求与历史问答属于同一"问题家族"，
   且该类需求在本空间全部问答中已出现 ≥2 次。
2. **多步任务完成**：单次会话完成 ≥15 个工具调用、或修复了一个棘手错误、或发现了一条明显可复用的流程。
3. **用户显式要求**：用户提出"沉淀 / 固化 / 复用流程""做成 skill""把这个流程保存下来"等意图。

触发后，先按"执行流程"判定是否真正沉淀；不盲目创建。

## 需求聚类 key（如何判定"同一类"）

不按具体页面 URL 或文件名，而按"问题家族"聚类。每个 key 形如 `领域-操作`：

- 示例（本家装平台项目已出现的家族）：
  - `worker-contract-flow`：工人合同创建 / 乙方选填 / 跳转目标 / 状态流程
  - `prd-sync`：原型改动后同步 PRD 章节、状态机、TOC
  - `nav-fix`：右侧导航项新增、错链修复、演示开关移除
  - `owner-page-build`：业主端页面补建与接入导航
- 聚类规则：以"功能域 + 操作类型"归并；同一页面多次同类改动归同一 key；
  跨页面但同性质的改动（如多处错链修复）归同一 key。

## 跨会话频次判定（核心）

**优先用 `conversation_search` 工具实时检索历史对话**，而非依赖本地频次表：

1. 以当前需求 key 的中英文关键词构造查询（自包含、描述清楚，不含当前上下文）。
2. 调用 `conversation_search`，在返回结果中统计"同类需求被实际处理"的次数。
3. 若历史命中 ≥1 且加上本次 ≥2，判定为"重复需求"，进入沉淀流程。
4. 可选辅助：若项目 `MEMORY.md` 已存在「需求频次表」，可合并累加；但本 skill **不强制要求**先写入 MEMORY.md。

> 这样设计使本 skill 能独立跨会话整合，无需预先配置记忆文件。

## 排除项（不沉淀）

出现以下情况，跳过沉淀并简要说明原因：

- 纯一次性探索 / 查询 / 简短问答；
- 误判纠正本身（除非纠正揭示的"正确路径"具有普遍复用价值）；
- 已被现有通用 skill 覆盖的能力（如 `chinese-git-workflow`、`chinese-code-review`、
  `systematic-debugging` 等），不重复造轮子；
- 涉及敏感信息或仅对单次会话有效的临时方案。

## 执行流程

1. **识别需求 key**：用"需求聚类 key"规则为当前需求命名。
2. **判定频次**：按"跨会话频次判定"检索历史，确认同类出现 ≥2 次且不在排除项内。
3. **整合历史问答**：用 `conversation_search` 拉取该类需求的全部相关历史，
   提炼出可复用的步骤、约束、坑点、最终正确做法（去除一次性噪声）。
4. **设计新 skill**：
   - 命名：`lzjbc-<短横线小写 key>`（如 `lzjbc-worker-contract-flow`）；
   - `description`：第三人称、含具体触发词（"此 skill 应在…时使用"）；
   - 正文：用祈使/不定式指令式，含目的、触发条件、执行步骤、安全约束；
   - 仅在确有必要时新增 `scripts/`（确定性代码）或 `references/`（大文档），保持 SKILL.md 精简（<5k 词）。
5. **创建文件（仅新增，不改现有）**：
   - 路径：`skills/<skill-name>/SKILL.md`（与项目现有 skill 并列）；
   - frontmatter 必须含 `name`、`description`、`agent_created: true`。
   - 用 Write 工具创建，不修改任何已有文件。
6. **展示初版并确认**：将新建的 SKILL.md 通过 `present_files` 呈现给用户审阅，
   遵循项目"先确认后改"协作约定——在用户确认前，不进一步把它接入正式流程。
7. **记录（可选）**：若用户后续决定启用 MEMORY 频次表，再追加到 `MEMORY.md`；本 skill 初始不强制。

## 安全与约束（最高优先级）

- **禁止修改任何现有原型 / PRD / 代码 / 文件**：本 skill 只新增 skill 文件，不做任何就地编辑、删除、重命名。
- **先确认后改**：生成新 skill 后先展示给用户，确认后再视为正式沉淀。
- **不破坏既有交互**：新 skill 的流程描述不得暗示改动其他模块。
- **命名隔离**：新 skill 统一加 `lzjbc-` 前缀，避免与 20 个通用 skill 混淆。

## 示例

用户第三次提出"工人合同详情页变更阶段多状态流程样式打磨"类需求 →

1. key = `worker-contract-flow`；
2. `conversation_search` 检索命中此前两次同类（新建跳转纠偏、状态流程一致性），
   累计 ≥3 次，且不在排除项；
3. 整合三次历史，提炼"worker_draft=撤回后语义 vs 新建初始态必须分流到不同页面"等坑点；
4. 设计 `lzjbc-worker-contract-flow`：含状态模型、页面分流规则、校验留痕步骤；
5. Write 创建 `skills/lzjbc-worker-contract-flow/SKILL.md`（带 `agent_created: true`）；
6. `present_files` 展示给用户确认。
